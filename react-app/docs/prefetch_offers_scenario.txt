Exactly — that’s the behavior we want:

Normal scenario:

User clicks a product that is not being prefetched → runs openProduct as usual, fetches offers from API or cache.

Prefetch scenario:

User clicks a product while it’s being prefetched in the background →

Prefetch is aborted using prefetchService.removeFromQueue([productId]).

The product is removed from the prefetch queue.

openProduct then runs normally for the user-triggered fetch.

⚡ Key points:

Prefetch is “fire-and-forget”; it doesn’t block the UI.

User-triggered load always wins.

isOffersLoading and state updates behave as normal, no extra flags needed.
